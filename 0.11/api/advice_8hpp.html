Detailed Description

The advice file (design doc 17, issue #26): typed hints for the router, written by a person, a script or a language model, and read by the engine like any other input.

The engine never talks to a model; a model is one possible writer of this file.

{ "version": 1, "note": "free text, logged and never acted on", "variants": 4, // advised variants added to the portfolio (default 4) "first_nets": ["USB_DP", "USB_DM"], // routed first; other nets do not rip them "priority": [["U1.A1", "J2.3"]], // connections (pad to pad, either order) routed first "layers": {"no_tracks": ["In2.Cu"], // no new tracks on these copper layers (vias still pass) "cost": {"F.Cu": 1.5}}, // track cost factor per layer (1 to 1000) "regions": [{"name": "north channel", // a region of the board (millimetres, the board file's axes) "rect": [10, 10, 20, 14], // or "polygon": [[x, y], ...] "layers": ["F.Cu"], // default: every copper layer "reserve_for": ["NET1", "NET2"], // only these nets may put copper there ... "avoid_nets": ["NET3"], // ... or: these nets may not (exactly one of the two) "tracks": true, "vias": true}] // which copper is kept out (both by default) }

Advice never contains copper and never changes a rule's value: it changes the order of the connections, the cost of a layer, and where some nets may not go, all inside the router's search. Every route is still judged by the exact check, and the advised attempts run as extra portfolio variants next to the unadvised ones, so the winner can only be better.

Reading is strict, as for the rule overrides (doc 15 §6.3): an unknown key, a wrong type or a value out of range is an error naming the file and the entry, never ignored (a typo must not silently drop a hint). Names are checked against the board by check_advice_refs; entries that have no effect are warnings.
