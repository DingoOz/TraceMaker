3// Gridless legalisation of routed copper (doc 05 §41.3, D104).
4//
5// The lattice router places every track on a lattice point and cannot move one it has committed, so a solution found under
6// looser rules (smaller clearances) usually has room to spare that the lattice cannot use. This module takes such routes and
7// moves the vertices of their tracks and vias (the topology, layers and order along every channel stay as they are) until
8// every clearance of the board's real rules holds, or as many as it can: a vertex is pushed along the normal of each pair of
9// copper items that are too close, by Gauss-Seidel sweeps over the pairs (position-based dynamics, Müller, Heidelberger,
10// Hennix and Ratcliff, J. Vis. Commun. Image Represent. 18(2), 2007). A prototype that solved the same problem by sequential
11// linear programming (HiGHS, minimum total movement) did about as well (6 stuck srj20 boards, 0.06 mm solutions to 0.10 mm: LP 3
12// legal and 3-11 pairs left on the others, projection 2 legal and 2-9 left). What remains
13// violated is dropped and routed again by the caller, and every route that is kept passes the router's exact check, so the
14// heuristic can lose work but never legality.

25struct LegalizeOptions {
26 double box_mm = 0.25; // a vertex stays within this distance of where it started
27 double margin_mm = 0.003; // clearance asked for beyond the rule (rounding to nanometres, the pairs between sweeps)
28 int sweeps = 300; // projection sweeps at most
29 double edge_mm = 0.035; // copper stays this far inside the board outline (plus the rule's edge clearance)
30 // > 0: every unlocked route track is cut into pieces of at most this length (at the vertices of same-net copper that lie on it, and evenly
31 // in between), so that a long straight track can bend where its neighbours are too close, instead of only moving as a whole; after the
32 // sweeps the vertices that stayed on a straight line are merged again. 0 = the vertices the routes have (unchanged behaviour).
33 double subdivide_mm = 0;
34 std::uint64_t seed = 0; // != 0: the pairs are visited in another (seeded) order, which leaves other pinches unresolved: portfolio variants differ
35 std::vector<geom::Point> outline; // board outline polygon (Obstacles::outline()); empty = unbounded
36};

38struct LegalizeResult {
39 int nodes = 0; // vertices of the routes (tracks and vias merged by net and position)
40 int moved = 0; // vertices that ended up elsewhere
41 int pairs_before = 0; // pairs of copper items closer than the rules allow, before and after
42 int pairs_after = 0;
43 double max_move_mm = 0;
44 int sweeps_used = 0;
45};
