# Overnight decisions and assumptions (2026-10-02 → 03)

Decisions made without asking, as instructed. Each is reversible; reasons in one line.

| # | Order | Decision | Why |
|---|---|---|---|
| A1 | – | Local git commits at each milestone or significant step (no push, no remote, no Claude attribution) | Gives you history and rollback points; nothing leaves the machine |
| A2 | – | Order of work: M1 → M2 (core DRC checks) → M4 (first router + harness) → M3 (viewer), with M3 started in parallel by a helper agent when the event schema exists | Router value first; the viewer needs routing events to be interesting |
| A3 | – | Schematic netlists come from `kicad-cli sch export netlist` for now; a native `.kicad_sch` connectivity resolver is deferred to schematic-to-board work (M7/M8) | Board files already carry pad nets; resolving schematic connectivity natively is large and not needed for routing |
| A4 | – | Ground truth for parser/geometry tests comes from KiCad's own `pcbnew` Python inside the Docker image (`scripts/kicad_truth.py`); truth JSON is committed in `tests/truth/` | Tests compare against KiCad itself, not my reading of the format |
| A5 | – | Read both KiCad 9 (`(net 3 "GND")` + net table) and KiCad 10 (`(net "GND")`) net syntax; write back in the style that was read | Demo set mixes both; writing in the read style keeps diffs minimal |
| A6 | – | Repository-local git identity: name `dingo`, email from your Claude account. Global git config untouched | Commits need an identity; change with `git config user.name` |
| A7 | – | Footprint flipping (top↔bottom) is not implemented in the M1 editor; it comes with placement (M7), where side changes are needed | Flipping mirrors every child item and swaps layers; not needed for routing |
| A8 | – | Zone and pad-primitive arcs are flattened to their start/mid/end points for now; exact arc geometry comes with the M2 geometry kernel | Enough for reading; DRC needs exact shapes |
| A9 | – | Effective net class = explicit assignment, else first matching pattern, else Default (KiCad 9+ can combine several classes by priority; not modelled yet) | Matches all demo projects; multi-class merging is rare |
| A10 | – | ~~Board minimum clearance is not a floor~~ **Retracted later:** KiCad does apply it as a floor (it reports the 24 violations on multichannel_mixer). | A11 | – | M2 DRC parity is "good enough to route against", not complete: 11/16 KiCad demo boards match kicad-cli exactly on 15 routing-relevant violation types (regression-tested); on fuzzed PCBench boards widths, via sizes, annular rings and drills match, while short/dangling/zone-edge classification on deliberately broken copper still differs. | A12 | – | Rule sources implemented from KiCad behaviour observed with kicad-cli: local pad/footprint clearance overrides beat net classes; coupled diff pairs use min(clearance, diff-pair gap); board minimum is a floor; project rule severities (ignore) are honoured; boards without a project use KiCad defaults plus legacy `(setup)`/`(net_class)` rules from the board file; KiCad caps each violation type at 199 reports | Each verified on a specific demo board (see comments in src/drc/rule_engine.cpp) |
| A13 | – | Dropped `-Wnull-dereference` from the warning set | GCC 15 at -O2 reports false positives on plain `std::vector` element writes; ASan/UBSan presets still catch real null dereferences |
| A14 | – | Plated through-hole pads are on all copper layers regardless of their layer list; old boards' custom copper names ("Front") map to canonical names by layer number and are written back with the file's own names | Both observed on PCBench boards against kicad-cli |
| A15 | – | Weighted A* (1.25) tried and reverted to 1.0 by default (kept as --heuristic-weight) | Tier-A clean pass fell from 92.5% to 82.5% with it: greedier paths waste routing space |
| A16 | – | Benchmark "added errors" count only KiCad violations involving a track, arc or via (router-introduced); other added types are kept as diagnostics (`added_any`) | KiCad's report of pad-versus-footprint-graphic clearances changes when nets get connected (PCBench Microdox/ErgoDone) without any routed copper involved; Freerouting's harness also counts router-introduced violations |
| A17 | – | Pad solder-mask openings keep the pad's net even on the side where the pad has no copper (edge-connector fingers), so tracks may not enter them; such pins stay unrouted rather than create bridges | Verified on fifogfx_c64cart: routing the fingers produced 81 KiCad solder_mask_bridge errors. | A18 | – | Solder-mask graphics (lines, closed loops, polygons, circles) are grown by the board pad-to-mask clearance before the router keeps other copper out of them | Inferred from kicad-cli on PCBench Horticulture: a track 0.17 mm from a mask line was a bridge with 0.2 mm expansion; with the growth the board routes clean |
| A19 | – | Copper text obstacles are estimated boxes grown by 15% of the text height on every side (plus stroke thickness) | KiCad glyphs reached 0.12 mm past the tighter box on PCBench USBI2C01 (one clearance error in run final6-tierB); exact glyph outlines from KiCad would remove the margin |
| A20 | – | Extra diversified restarts, adaptive GPU-field cut-off and portfolio early stop act only on wall-clock runs or leftover budget; `--work` runs stay byte-identical across repeats | Determinism is needed for regression tests and comparisons |
| A21 | – | Text on F.Mask/B.Mask is a solder-mask opening, modelled with the copper-text box estimate grown by the board mask expansion | Found on held-out PCBench boards (FRM16 relay controller, MySensors IR Blaster): routing under mask text produced KiCad solder_mask_bridge errors |
| A22 | – | Default via cost 3 mm of track (was 1 mm); post-routing clean-up (via-saving re-routes, then path smoothing) on by default; portfolio variants get a grace period of 2T + 5 s after the first complete variant (T) instead of stopping at once | Dev-set runs (tiers B and C, same load): clean-up alone cut vias 13–20% and bends about 40% at equal length; via cost 3 cut vias 25–33% at +1–2% length; clean pass equal within one board (USBI2C01, known to vary). The grace period lets a cleaned-up variant win selection |
| A23 | – | Pads with the same number in one footprint are one electrical pad for clearance/short checks; overlapping pads of the same footprint connect; chamfers apply to round-rect pads (core chamfer c − r(2 − √2)) | KiCad DRC parity on the jetson-agx-thor-baseboard (12 false shorts) and RoyalBlue54L-Feather (31 false shorts, 8 false clearance errors, 1 false unconnected) demo boards |
| A24 | – | A footprint's own solder-mask graphic that touches pads of exactly one net of that footprint is that pad's opening: copper of that net may enter it (other mask graphics stay net-less openings) | DAC 2020 boards draw every pad opening as an F.Mask polygon; treating them as net-less walled every pad in (bm11 37% → 100%, bm10 60% → 100% routed, both clean in KiCad) |
