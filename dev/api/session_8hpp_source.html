3// A board session an agent can drive (design doc 19, milestone M18).
4//
5// The agent lists the open connections, asks the engine to route some nets with some hints, looks at the result, rips a net, goes back to an earlier
6// state and saves. The engine is what it was: copper comes only from the router (every segment and via passes the exact check), a call is a
7// transaction that is kept or not, hints are an advice file (doc 17) read by the same code, and the log of calls replays to the same bytes.
8//
9// One `Session::call` serves every transport (MCP and JSON lines, transport.hpp). It never throws: a refused call is {"error": {"code", "message"}}.

27struct SessionOptions {
28 std::string in; // the board; its project files supply the rules
29 std::string out; // where `save` writes; empty = `save` is refused
30 std::uint64_t seed = 1; // router seed of a `route` call that does not give one
31 long work_limit = 0; // search work of the whole session (expansions plus flood cells); 0 = none
32 int gpu_device = -1; // GPU for cost-to-go fields; -1 = CPU reference (same results)
33 int threads = 4; // portfolio threads of a `route` with several variants (the result does not depend on it)
34 std::string log; // JSON-lines log of the calls; empty = none
35 events::Sink* sink = nullptr; // the router's events (the viewer)
36};
