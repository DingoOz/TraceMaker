3// The advisor protocol (design doc 17 §5): an advisor is any executable that reads a stuck report (JSON) on stdin and writes
4// an advice file (JSON) on stdout. The engine starts it through the shell, with a time limit, and treats whatever comes back
5// as untrusted: the answer must be exactly one advice file and passes the same strict checks as a file written by hand.
6// A missing, slow, failing or nonsensical advisor is a warning, never an error of the run (rule 5, doc 17 §6).
