3// Escape planning, version 2 (roadmap M9; design doc 05 §3 and §14): min-cost-flow channel assignment for deep
4// ball-grid arrays, layer by layer.
5//
6// Version 1 (escape.hpp) sends perimeter pins straight out and every inner ball to a fixed dog-bone via site. In
7// an array deeper than two rings that leaves the channels between balls unassigned: which inner ball uses which
8// gap, on which layer, is decided by whichever net's search runs first. Here each deep array gets the
9// network-flow escape model with diagonal capacities (Yan & Wong, "A correct network flow model for escape
10// routing", DAC 2009): the square gaps between four balls are graph nodes, the gap between two neighbouring balls
11// is an edge whose capacity is the number of tracks that fit there, and every gap node carries a capacity from its
12// diagonals, which every track turning in or crossing the gap must pass (we take the narrower diagonal for both,
13// which is conservative). A min-cost max flow from the balls to the outside of the array gives each escaping ball
14// a channel sequence. Layers are assigned one after another, as in the layer-by-layer escape of Ozdal & Wong
15// ("Algorithms for simultaneous escape routing and layer assignment of dense PCBs", TCAD 2006) and Lin et al.
16// (DAC 2021): the pad layer first; the balls that cannot leave on it get a
17// dog-bone via site (an assignment, also by min-cost flow, to interstitial sites no pad-layer escape crosses);
18// then each further layer routes the remaining vias out between the via sites, which are that layer's obstacles.
19//
20// The result is a set of corridors the router reserves exactly as version 1's: reservations only remove options
21// from other nets, every commit is still checked exactly, so the plan cannot create violations. Integer costs,
22// pads and layers in board order and fixed arc order make it deterministic.
