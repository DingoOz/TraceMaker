3// Rule fit (route --fit-rules, doc 20 §2.8, D194): relax the rules a board's own copper already breaks, to what that copper has.
4//
5// A board whose pads or existing tracks break a rule cannot be routed under that rule the way it was laid out. The designer-oracle test
6// (bench/records/oracle-2026-11) found this on boards that never complete: card-edge connector pads inside the copper-to-edge clearance,
7// tracks closer to holes than the hole clearance, tracks narrower than the minimum width. All PCBench boards are in the KiCad 5 format,
8// which stores no edge or hole clearance, so KiCad 10's defaults (0.5 mm and 0.25 mm) hold for boards designed without them.
9//
10// The fit runs the DRC on a reference board (the input, or an earlier layout of it), takes for every fitted rule the smallest value its
11// violations measure (for the clearance, their low decile), and lowers the rule to that value, never below a floor. With tracks on the reference it also lowers each net
12// class's track width and via size to what the reference's tracks of that class use. It only ever relaxes, and every change is reported.
13// The output then breaks the board's stated rules where the fit relaxed them: KiCad's DRC reports those, as it does for the reference.

22struct FitOptions {
23 Coord clearance_floor = 90'000; // no clearance is fitted below this (a common fab limit for multilayer boards)
24 Coord width_floor = 90'000; // nor a track width
25 Coord edge_floor = 0; // copper may reach the edge when the reference's does (card-edge fingers)
26 Coord hole_floor = 0;
27 Coord annular_floor = 50'000;
28 Coord via_floor = 300'000; // via diameter
29 Coord drill_floor = 150'000;
30 double clearance_quantile = 0.1; // the clearance is fitted to this quantile of the measured gaps, the other rules to the smallest
31 int min_evidence = 3; // fewer violations of a kind are taken for slips and fit nothing
32};
