3// The session daemon (`tracemaker daemon`, design doc 19 §10, milestone M18): board sessions (session.hpp) that outlive the process that
4// asked for them, so a client that runs once per user action — the KiCad plugin — keeps the board read, the rules, the states and their
5// caches (open connections, DRC errors) between actions.
6//
7// Transport: a Unix-domain stream socket that only its owner can open (the directory is 0700, the socket 0600), JSON lines, one request
8// per line and one answer per line. Clients are served one at a time, in the order they connect: a session is one board and one user,
9// and the router already uses the cores.
10//
11// {"op": "status"} -> {"sessions": [...], "version"}
12// {"op": "open", "board": PATH, "key": K, "fingerprint": F, "out": PATH, "work_limit": N, "seed": S}
13// -> {"session": ID, "reused": bool, "state"}. With `key` (the client's name for the board, e.g. the path KiCad has open) and a
14// `fingerprint` equal to the one recorded for that session's current state (`mark`), the session is reused and `board` is not
15// read; otherwise a new session is started from a copy of `board` and its project files (the client may delete them).
16// {"op": "call", "session": ID, "tool": T, "args": {...}} -> {"result": ...} (Session::call, doc 19 §4)
17// {"op": "diff", "session": ID, "from": STATE} -> Session::copper_diff
18// {"op": "mark", "session": ID, "fingerprint": F} -> records F for the current state (what the client's board now looks like)
19// {"op": "close", "session": ID}, {"op": "shutdown"}
20//
21// A refused request is {"error": {"code", "message"}}. The fingerprint is the client's: the daemon only compares strings. A client must
22// change it whenever anything the router reads changes (copper, footprints, zones, rules); a wrong match would route on a stale board,
23// which is why every route is still checked against the session's own board and the client commits only the copper the daemon returns.
