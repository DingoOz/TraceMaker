# 12 — Decisions and risks

> Part of the TraceMaker plan. Start at [`../PLAN.md`](../PLAN.md). Append new decisions at the end.

## Decisions

| # | Decision | Alternatives | Reason |
|---|---|---|---|
| D1 | Engine in C++20 + CUDA; viewer in TypeScript + WebGL2/WebGPU; harness and plugin in Python | Rust core (as KiCadRoutingTools); all-Python | CUDA ecosystem, existing C++ design, GCC 15 + nvcc available; Python is what `kicad-cli`/IPC tooling uses |
| D2 | Placement is in scope, with four explicit optimality levels | Report-only placement (clean-sheet doc) | User requirement; honest claims instead of "optimal" in name only |
| D3 | Analytic global placement, then SA/LNS, then CP-SAT windows | SA only (SA-PCB); GA only (Allegro X AI); RL (RL_PCB) | Analytic gives a provable relaxed optimum and a strong start; SA handles discrete PCB moves; CP-SAT gives exact local optima |
| D4 | Detailed routing first on a fine octilinear lattice with exact validation; gridless tile plane later | Gridless first (clean-sheet doc); Manhattan lattice (OrthoRoute) | Faster to make correct, GPU-friendly; Manhattan-only routing scores poorly on mixed boards |
| D5 | GPU accelerates fields, batches, broad-phases and placement — never the final legality decision | GPU end-to-end router | Quality and determinism; CPU reference for every kernel |
| D6 | Failure memory with four tiers (search, run, strategy, persistent) | History cost only | User requirement; each tier has published precedent |
| D7 | KiCad `.kicad_pcb` native I/O; DSN only for benchmarks/legacy | DSN/SES as main path | DSN loses rules (Freerouting evidence: 33/99 clean pass) |
| D8 | KiCad DRC (`kicad-cli`) is the benchmark judge | Own DRC only | Own DRC can be wrong in ways that hide errors |
| D9 | Integer fixed-point costs everywhere decisions are made | Floating point | Bit-identical CPU/GPU, deterministic atomics |
| D10 | Viewer in the browser, served by the engine; WebGL2 baseline, WebGPU when available | Native ImGui/Qt; WebGPU-only | Remote use from any machine, GPU rendering, no install; WebGPU is not yet default on Linux Firefox |
| D11 | Own CUDA kernels for placement and routing; no PyTorch/DREAMPlace runtime dependency | Embed DREAMPlace/Xplace | PyTorch wheels dropped Volta; CCCL 3/cuCollections partly untested on Pascal; BSD-3 code is ported, not linked |
| D12 | FLUTE (BSD-3, from OpenROAD `stt`) for Steiner trees | GeoSteiner | GeoSteiner is CC BY-NC (non-commercial) |
| D13 | Full placement aims for a 0.25 mm courtyard gap (board rule if present), falling back to KiCad's default of 0, then to keeping unplaceable parts at their input positions, then to the refine result | Always 0; always 0.25 mm | Most human boards are packed below 0.25 mm; the fallbacks keep full mode usable on dense boards |
| D14 | Global spreading uses SimPL rather than the electrostatic method | ePlace/DREAMPlace-style density | Simpler on CPU and adequate for PCB part counts (doc 04 §7) |
| D15 | Placement keeps a new placement only if it routes at least as well as the input under the same router budget (`--route-check`, `--mode auto`) | Trust HPWL | Lower HPWL from denser packing routed worse on PCBench (13 vs 15 fully routed boards) |
| D16 | Large boards (≥ 3M lattice points per layer) get two portfolio variants at double pitch | One pitch for all variants | Fine-pitch lattices are time-limited on large boards (P8000: 325 → 334 of 361 in 120 s) |
| D17 | The CLI's `route` and the Python module's `route()` call one function (`tmk::app::run_route_job`); the KiCad plugin uses the module in-process when importable, else the binary | Bindings that drive `Router` directly; plugin with the binary only | Identical results by construction (tested byte for byte); no subprocess when the module fits KiCad's Python, and the binary still works when it does not |
| D18 | With bindings on, the whole build is position independent (`-fPIC -fno-semantic-interposition`); bindings are off in sanitizer builds | A second PIC copy of the engine libraries; shared engine library | One set of objects; routing output and speed unchanged (C-BISCUIT: same board, 5.29 s vs 5.30 s); an instrumented extension cannot load into a plain interpreter |
| D19 | PCM package uses metadata schema v2 with `runtime: ipc`, does not bundle the engine by default (env `TRACEMAKER` / `TRACEMAKER_PYTHONPATH`), optional Linux bundling; licence field defaults to GPL-3.0-or-later until the project licence is chosen (requirement N8) | Always bundle binaries | Native builds depend on the system's CUDA runtime, SQLite and libstdc++ and the module on the Python version; KiCad 10 ships PCM schema v2 and kicad-python 0.8 validates against it |
| D20 | Parallel tempering is *annealed* replica exchange: the ladder (refine: 16× → 1× the annealing temperature; full: √8× → 1/√8×) follows the annealing schedule, exchanges decided at a barrier from a dedicated stream | Fixed ladder T0 … 1e-4·T0 (textbook PT); independent runs only | The fixed ladder accepted ~3 % of exchanges and cost +5 % vs independent runs; the annealed ladder is −4 % (refine, 23 boards) at the same move budget and identical for any thread count (doc 04 §8) |
| D21 | Routability term is RUDY overflow + pin density on a ≤ 32×32 grid, integer nm, power nets excluded; the router loop shrinks bin capacity around failed connections | Electrostatic `R(x)` in global placement; airwire-crossing density only | Cheap to keep incremental and exact in the annealer (reference = from-scratch recompute); capacity shrinking is the PCB analogue of RePlAce cell inflation |
| D22 | Router-in-the-loop and ECO take the router as a callback (`RouteFn`) and accept a placement only if it leaves fewer connections unrouted (ties: shorter HPWL for seeds only) | Link tm::route into tm::place; accept on estimated overflow | Keeps tm::place independent of the router and testable with a synthetic router; the router's verdict, not an estimate, decides (rule 4) |
| D23 | Exact windows (doc 04 §3 F) by own branch and bound over candidate slots (own spot, other window parts' spots, HPWL-median spot; 4 rotations), not CP-SAT | OR-Tools CP-SAT | OR-Tools is not installed; B&B is exact over its candidate set, has a full-enumeration reference path, and is small enough to run inside annealing |
| D24 | `--route-check` restores a rejected placement by copying the input file | Re-saving the edited document | The editor edits the document in place, so re-saving wrote the *new* placement while reporting "kept input" (M7 bug, fixed 2026-10-03) |
| D25 | Decoupling capacitors are tied to the nearest IC supply pin (in the input placement) by a two-pin pseudo-net at signal weight (`PNet::affinity`), counted in the objective only; on by default, `--no-decap-affinity` turns it off | Hungarian assignment + distance constraint (doc 04 §2) | Power nets carry weight 1, so full placement moved decaps 4 → 16–19 mm from their ICs (place_intent.py). The pseudo-net keeps every placer stage (B2B, annealer, LNS, bound) exact and unchanged and brings decaps to 1.8–3 mm (closer than the human layouts) for 1–9 % more HPWL. Assignment by optimisation is still open. |
| D26 | The component-rule catalogue stays `docs/component_rules.yaml`; `scripts/crules_catalogue.py` writes `src/crules/catalogue.json`, which the build embeds; a ctest fails if the JSON, the YAML and the rule ids in doc 15 drift | A YAML parser in the engine; JSON as the edited source | One small generated file instead of a new dependency; the YAML keeps comments and stays readable for people editing rules |
| D27 | `lib_id` detectors match the footprint name only, unless the pattern names a library (`connector_usb:`, `rf_module:`) | Match the whole `library:footprint` string | Library nicknames are free text: on PCBench UCCBPCB the nickname `usb_ccb_custom:` made an MCU, a jumper and headers "USB connectors" (precision first, doc 15 §9.1) |
| D28 | Component proximity rules reuse D25's objective-only two-pin pseudo-nets (`ExtractOptions::affinities`): weight 10, ×2 for a protection part to its connector; each part is pulled by one rule (crystal > oscillator > ESD > regulator > decoupling), D25's own ties are kept unchanged and win | Hard distance constraints in the legaliser; a separate cost term | Same exact incremental cost in every placer stage; reported HPWL/crossings/congestion unchanged; no conflicting pulls on one part; `off` reproduces the previous placer byte for byte |
| D29 | Generated keep-outs (crystal + load caps XTAL-04, switching inductor BUCK-06/BOOST-04) are rule areas on the copper layers where none of the parts has a pad and no other part has a pad inside, tracks only, used by the router only with `--component-rules on` and never written to the output; the full net-exempt rule (all layers, tracks and vias) goes to the sidecar `<output>.tracemaker.kicad_dru` as `intersectsCourtyard` rules | Keep-outs on every layer; editing the user's `.kicad_dru` | KiCad rule areas cannot exempt nets, so a keep-out on a part's own pad layer would cut its pads off; `soft` adds no hard constraints (doc 15 §3.5); rule 8 forbids touching the user's files. KiCad's DRC reads the sidecar (checked on PCBench CANadapter) |
| D30 | Per-net coupled routing through `RouterOptions::pair_nets` (pairs routed coupled first when `diff_pairs` is off), filled from detected USB 2.0 D+/D- pairs with `--component-rules soft` or `on` | Name-based P/N detection only (`--diff-pairs`, all or nothing) | USB nets are often named DP/DM (not P/N or +/-); a three-line hook (`pair_wanted`) keeps the router change minimal while the router is being changed elsewhere |
| D31 | `--component-rules` defaults to `off` for both `tracemaker-place` and `tracemaker route`; `soft` is opt-in | Default `soft` (doc 15 §3.5 planned it once the §9 gates pass) | Measured on the 23-board placement set, 9 ESD boards and 6 boards × 3 seeds (doc 15 §14.3): `soft` brings crystals 6.4 → 5.1 mm, ESD parts 7.1 → 3.2 mm and load caps closer at equal HPWL, but decoupling and regulator caps move away on some boards (decaps worse on 9 of 18 runs); doubling the decap ties fixes that for +2–3 % HPWL. Held-out detection recall for USB connectors, connectors and mounting holes is below the 0.8 gate. `off` reproduces the previous output byte for byte |
| D32 | Escape planning v1 is reserved corridors (perimeter out, dog-bone for inner SMD balls) checked by the normal router, not a min-cost-flow pre-route | Min-cost-flow escape routing first (doc 05 §3) | The BGA failures were mostly infeasible under the fixture rules or time-starved strict passes; corridors fix the "channel taken first" case cheaply (logicbone +26, decelerator +33 at a fixed budget) and cannot create violations. MCF stays open for deep arrays |
| D33 | Escape planning runs in two of the eight portfolio variants (not all) | All variants; opt-in only | All variants: tier B +8 connections, tier C −7, BGA set +31, tier A equal: neutral on average, so it is an arm the portfolio can pick where it helps |
| D34 | The escalation rung necks vias down to the smallest via the board minimums allow (drill ≥ 0.2 mm) | Net-class via only | KiCad checks vias against the board minimums; d20_tri +24, OtterCast +17 with 0 added KiCad errors |
| D35 | Escape feasibility (`tracemaker escape`) is reported beside the clean pass (`dead_pins`, `clean_pass_feasible`), never instead of it | Drop infeasible boards from the benchmark | PCBench ships no `.kicad_pro`; some boards cannot be routed clean by any router under the rules they are judged by (designers' own boards fail them). Hiding them would flatter both tools |
| D36 | Impedance rules (P4) are computed and reported only: width/gap per routing layer from the board stackup in `tracemaker rules`; routing widths and net classes are unchanged and `--component-rules` stays `off` by default | Synthesise per-layer net classes and route with them | The benchmark has no stackups (0 of 1,157 PCBench `unrouted` files), the formulas carry ±2–8 % model error plus ±10 % fab tolerance, and the reference-plane assumption is not yet checked by plane coverage; a report lets a designer confirm before anything is enforced (doc 15 §14.5) |
| D37 | Closed-form models: Hammerstad & Jensen microstrip, Cohn/Wheeler stripline, Kirschning & Jansen coupled microstrip, Cohn coupled stripline, Ghione & Naldi GCPW; off-centre striplines by Wadell's image split; quasi-static, solder mask ignored; width/gap by integer-nm bisection | A 2-D field solver; KiCad's calculator code (GPL, and its coupled-stripline thin-gap branch drops √εr) | Same physics as KiCad's PCB calculator so users can cross-check; independent implementation from the papers; deterministic; agreement with KiCad 0–3 % and with exact conformal results to 1e-6 (doc 15 §14.5) |
| D38 | The copper layer adjacent to a routing layer is taken as its reference plane (microstrip outside, stripline between the neighbours inside); a ground zone on it is reported as confirmation, otherwise "(assumed)" | Require a zone; search for the nearest plane-typed layer | KiCad boards rarely type planes as `power`; 2-layer boards pour GND on the far side; the report keeps the assumption visible per layer |
| D39 | Pairs are solved at the Default net class's diff-pair gap (≥ its clearance and the board minimum); the width is solved, and only if the width would fall below the board minimum (≥ 0.1 mm) is the gap solved instead | Solve width and gap jointly for Zdiff and a common-mode target; fixed S = W | One free variable keeps the result unique and deterministic; the gap the board already uses is the one the router will keep |
| D40 | The user override file (doc 15 §6.3) is JSON read by the engine (`--rules-override` on `rules`, `route`, `tracemaker-place`); YAML is converted by `scripts/crules_override.py`. Unknown keys, rule ids, categories, parameters, value types and board references are errors; an entry that names a part not detected as its category is a reported warning | A YAML parser in C++; silently ignoring entries that do not apply | Same approach as the catalogue (D26: no YAML library for one file); a typo must never drop an override, but a board edit must not stop routing when the catalogue default (the conservative side) still applies |
| D41 | ETH-05 (no copper under discrete Ethernet magnetics) becomes a generated keep-out like XTAL-04: tracks, vias and zones on the magnetics' side and the adjacent copper layer where the magnetics have no pads, at confidence ≥ apply, used by the router only with `--component-rules on`; RJ45 jacks with integrated magnetics get none | A void on every layer; a void under MagJacks too | The catalogue says "same, adjacent" and "not required under integrated-magnetics RJ45" (TI SNLA387); keeping the area off the pads' layer keeps the transformer's own pins routable |
| D42 | Connector edge attraction is an opt-in placement objective (`--edge-attraction`): a one-pin pseudo-net from the connector body point nearest to the outline to the nearest outline segment's axis (x for a vertical segment, y for a horizontal one), weight 2 × signal; pin headers and sockets are not pulled | A virtual fixed part at the nearest outline point; a separate distance-to-polygon term in the cost | An axis anchor is exact in the integer HPWL the annealer already maintains incrementally (no new cost term to keep in sync), does not pin the connector to one point along the edge, and penalises rotating the mating side inwards; headers are mostly board-to-board or jumpers (CONN-01 note) |
| D43 | `--component-rules soft` in full placement runs in two stages: decoupling ties only (D25 and DEC-*), then those capacitors and their ICs are locked and the other component-rule pulls (crystal, load caps, ESD, regulator caps) refine from there (`--no-crules-two-stage` reverts) | One stage with all pulls (the first version); scaling the weights | One stage: decaps worse on 9 of 18 multi-seed runs. Weights (50/75 %) did not fix it on seeds 2–4. Two stages, 23 boards × 3 seeds vs off: decap median equal (3.66/3.42/3.74 vs 3.66/3.26/3.74 mm), crystal 5.11/6.70/5.07 → 4.66/5.77/4.72, load caps 2.38/4.77/3.11 → 2.03/2.76/2.39, HPWL geometric mean −1 %; 18 per-board metrics better, 4 worse (PocketBone decaps on all seeds). Component rules stay off by default |
| D44 | A flood-fill reachability pre-check runs before strict searches that are likely to fail (a retry with a larger window, or a connection that failed before); "no path" skips the A* and its cost-to-go field (`--reach-check 1`, default; 0 off, 2 every strict search; `--reach-verify` re-checks with the full A*) | Reusing the failed search's explored region on window growth; a coarse-grid check; checking every strict search | The flood uses the same legality tests with no bend states or costs, so it admits every A* path and its verdict is exact (0 mismatches under `--reach-verify`). 10 hard boards, one variant, 100 M: 8,285 → 8,332 routed, no board worse; every-search mode 8,336 but swings ±45 per board. Tiers A–D neutral (2,637 / 5,165 / 9,523 / 16,628 routed, clean pass unchanged). Region reuse would not keep the A* optimal in the larger window; a coarse grid would not be exact |
| D45 | Replay logs stay JSON lines (the live protocol, doc 13), zstd-compressed as independent frames when the file ends in `.zst` (snapshot in its own frame, frames closed every 1 MiB, checksums); plain `.jsonl` stays the default. Heatmaps are coarse grids (≤ 128 cells a side) of A* expansions and PathFinder history, sent by work done (every max(200k, budget / 40) expansions) | FlatBuffers for the protocol and the log now (doc 09 §2, §6); a custom binary record format; gzip | FlatBuffers is installed (flatc 23.5) but the message set is still changing (escape plan, component rules added in M9/M13), every message would need a schema in C++ and TypeScript plus a viewer decoder, and the gain is decode speed the viewer does not need yet. zstd on the JSON gives the compactness (12–13× on C-BISCUIT and CANadapter, 260 kB → 20 kB) with one small dependency, stays readable with `zstd -dc`, and keeps the Python tools (`report/render_events.py`, the record/replay test) working on the same text. Independent frames bound the loss when a run is killed and leave room for a seek index. FlatBuffers stays an open M3 task for when the message set is stable |
| D46 | Catalogue evidence gains a fourth code, **D**: the cited source was read and supports the rule, but gives no number, so the value is a TraceMaker default. D rules are demoted from hard to soft at run time like R rules; each verified rule carries a `checked` field (date, status, document, section/page). The 41 R rules were checked against their sources (doc 15 §8.10): 9 confirmed, 9 corrected, 11 left as defaults (D), 12 not verifiable (stay R) | Keep R for every rule with a TraceMaker default; mark the rules V once the qualitative statement is read | R meant "not re-read", which is no longer true for 29 rules; V would claim the numbers come from the source when they do not. D keeps both facts visible and keeps those rules from becoming hard by accident. No current D rule is hard and no engine-read parameter changed (RF-03, SHLD-01 and BUCK-07 values changed; their kinds are not enforced yet), so placement and routing are unchanged |
| D47 | The router portfolio's variant set is a setting (`--variants`), not the thread count: with `--work` it defaults to all eight variants for any `--threads`; the variants run on a pool of `--threads` workers in index order and the winner is the minimum of a total order (routed desc, vias, copper length, variant index). Without `--work` the default stays one variant per thread | Variants = threads (as before: `--threads 1 --work` ran variant 0 only, so the output changed with the thread count); successive halving first | Requirement N3: `route --work N --seed S` is byte-identical at 1, 2, 4, 8 threads (test `thread_determinism`); wall-clock mode is not deterministic anyway, so it keeps one variant per thread and its speed. Fewer threads than variants costs wall time, not quality; `--variants 1` reproduces the old single-router run byte for byte. `--time` is a safety stop per variant, counted from that variant's start |
| D48 | Side assignment (doc 04 §3 C/E, §9) is opt-in (`--flip`) and done by the annealer: a flip move (KiCad top/bottom mirror plus any turn, at the body centre or the nets' weighted median) for movable surface-mount parts on 2+ copper-layer boards whose footprint the writer can mirror exactly, plus a via-estimate cost (per net min(front, back) surface-mount pins × weight × `--flip-via-mm` 2). No FM/CP-SAT partition in stage (C), no side capacity in (B), no flips in ECO or exact windows. Orientation states become 0–7 (bit 2 = other side). The writer reproduces KiCad's `FOOTPRINT::Flip`, so a flip rewrites the footprint's child coordinates and layers (doc 04 §5 said only `at`, `layer` and pad layers change) | FM min-cut partition with area capacity per side, CP-SAT for ≤ 40 parts (doc 04 §3 C); flipping on by default | The annealer already holds the exact legality and incremental cost, so a flip move gets side assignment that respects courtyards on both sides, through-holes and copper for free; a partition before legalisation knows none of that. Off by default because double-sided assembly is a design decision and the via cost is real (23 boards: HPWL −7.9 % full / −7.6 % refine, crossings −31 %, but the via estimate rises 85 → ~480, routability unmeasured). Mirroring geometry by KiCad's own rules was verified against pcbnew on 2,529 footprints with 0 differences |
| D49 | Escape planning version 2 (min-cost-flow channel assignment on the pad layer, dog-bone sites by a second flow, then the same flow per further layer with the vias as obstacles; doc 05 §14) is opt-in (`--escape-flow`) and in no portfolio variant; one planning rule set per array (the most common class width/clearance/via), gap capacity from the narrower diagonal for all tracks | Replace version 1 in the two escape-plan variants; exact per-net capacities; Yan & Wong's separate per-diagonal accounting | One variant at fixed budgets on the 7 BGA-set boards with deep arrays: off 2,687, version 1 2,736, version 2 2,703 routed (better only on DoroidOscillo, +6 over version 1); narrower bands did not change that. A shared rule set keeps one power net from closing every channel; the narrower diagonal is conservative, so planned escapes always fit; the plan only reserves, so it cannot create violations (0 added KiCad errors on 3 outputs) |
| D50 | Differential pairs (doc 05 §15) are searched as one object: A* over (layer, lattice point, direction, side) with straight steps, 45° turns followed by a miter-safe straight run, and coupled via pairs, every move checked exactly on both tracks; breakout/fan-in legs validated lazily when a start or goal is popped; gap from the custom `diff_pair_gap` rule, else the net class's diff-pair gap, else the clearance between the halves. A ripped half takes its partner and the pair is re-tried coupled; the clean-up re-couples split pairs with exact restore; a pair that boxes in a pin between its pins is taken back. Off by default (`--diff-pairs`, `pair_nets`) | v1's centreline with an envelope disk and legs checked afterwards; routing the halves separately with a coupling cost; coupled copper dearer to cross in negotiation; budget held back for re-coupling; refusing pairs that straddle a pin | v1 coupled none of the USB hub's 5 pairs; v2 couples them at 84–94 % with 0 KiCad errors. On 18 boards (59 pairs) 35 pairs are ≥ 50 % coupled at the rule gap, completion 2,201 → 2,210, two boards −1 within fixed-budget noise. Separate routing cannot guarantee the gap; the dearer crossing cost PmodHDMIIn two connections; refusing straddling pairs lost edid-injector's 88 % coupling for nothing. Off by default because coupling costs space on dense boards and the pair detection is by name only |
| D51 | The DRC follows KiCad 10's connectivity on broken boards: net propagation before the checks (pads' net to the tracks/vias/board graphics of single-net clusters; zone-only vias take a zone's net), dangling tracks/vias judged on the any-net item graph, same-net items joined by copper overlap, KiCad's short/clearance split (zone overlaps are `clearance`; track/via overlaps short even net-less; pads short only with two nets), per-layer via reports, zero-clearance track/via-to-hole and edge tests, via/pad holes against fills, free vias, net-tie exclusions, KiCad's circle-in-rectangle gap (a via inside another net's rectangular pad is `clearance`), net-class drills for vias written without one, slots left out of hole-to-hole, and a zone's own clearance as a local clearance on its fill. The board reader no longer treats KiCad 9+ user layers typed `signal` (odd ordinals) as copper (multichannel_mixer-unrouted had 11 phantom copper layers; this also changes routing on such boards). Measured with `scripts/drc_broken_parity.py` (defects injected deterministically by `tracemaker selftest-defects`). The router keeps end-point connectivity and net-class clearance to fills for now | Keep file nets and anchor connectivity (TraceMaker's own, stricter notion of a short); emulate only the counts | KiCad's DRC is the judge and reads the board after propagation (verified in its 10.0.6 sources and on injected defects: a stray via on another net's track is no short there). The router changes (zone clearance, overlap links) alter routing and need a quick-tier run, so they are left for a follow-up |
| D52 | `tracemaker-place` defaults to `--component-rules soft` (proximity pseudo-nets for crystals, load caps, ESD parts, regulator caps and generalised decoupling; objective-only, two-stage in full mode per D43); routing's default stays `off` | Keep `off` (or `report`) until decap distances also improve | Placed tiers B and C (70 boards, rules off vs soft side by side): clean pass 28 → 28 and 18 → 18, routed 5,163 → 5,156 and 9,538 → 9,539; XTAL-01 median 6.54 → 5.57 mm, load caps 3.11 → 2.81 mm, decaps 3.17 → 3.17 mm (losses traced to the router keeping a different candidate). Full mode, 23 boards × 3 seeds (D43): crystal and load caps better, decaps equal. No routing cost, a measured gain for crystals; doc 15 §14.3 |
| D53 | The global congestion map (`--global-congestion`, doc 05 §16) stays off, and the rest of global router v2 (Steiner topology, via capacity, GPU pattern/maze port) is deferred | Turn the map on; continue with v2 | 18 hard boards at a fixed budget: 13,285 routed without, 13,289–13,294 with (noise); corridors 12,933. With cut-based capacities under 5 % of tiles reach 6/8 utilisation; about two thirds of unrouted connections on tiers B–D are boxed-in pins, which tiles cannot see |
| D54 | Connection planning weighs pad pairs by the gap between their copper, not by centre distance (`--plan-gap`, default on; doc 05 §17). The group re-route (R4 trial) is removed | Keep centre distance; keep the group re-route as an option | Fixed budget, one variant, 24 boards: 11,905 → 11,986 routed. KiCad-judged tiers A–D neutral (tier D side by side 16,618 → 16,622, clean pass equal), no added errors. The group re-route changed no board's result |

## Risks

| Risk | Likelihood | Mitigation |
|---|---|---|
| `nvcc 12.4` does not accept GCC 15 as host compiler | **Confirmed** | Use `-ccbin g++-12` (installed; builds for `sm_60`/`sm_70`; ran on the P100). Stay on CUDA 12.x because CUDA 13 drops Pascal and Volta |
| GPUs are shared with other workloads (llama-server held almost all GPU memory on 2026-10-02) | **Confirmed** | Memory admission control, batch shrinking, CPU fallback with identical results (doc 07 §4) |
| DRC parity with KiCad drifts across KiCad versions | Medium | Pin a KiCad version per release; parity tests in CI |
| Lattice routing misses tight gaps | Medium | Pin-access points, half-pitch last-gasp windows, gridless cleanup, tile-plane arm |
| Placement quality judged subjectively by users (mechanical, thermal intent not in netlist) | High | `refine`/`eco` modes by default for placed boards; rule areas and locks honoured; full mode opt-in |
| Negotiation oscillates | Medium | History decay, α scaling, reroute caps, best-board keeping |
| Learned components overfit the benchmark | Medium | Held-out board sets; learned arms only via bandit, never mandatory |
| Viewer slows the engine | Low | Lock-free rings, coalescing, drop-frontier policy |
| Scope (placement + routing + GPU + viewer) is very large | High | Milestones each deliver a usable tool; GPU and learning are additive to working CPU paths |
