# D178 — Placement advice: proposed placements as routability-loop seeds and ECO candidates

## Context

Milestone M16 (doc 17, issue #26) built stages 0-3: the stuck report, the router's advice file, advised portfolio variants and the
advisor protocol. Stage 4, "advisor-proposed placements as `seeds` of `routability_loop` and proposed moves as ECO candidates", was not
built (doc 17 §9). It is the part of the issue where a model's judgement (which part to move) would show (doc 17 §1). The user asked on
2026-11-13 to keep working on the open roadmap items.

## Decision

- A **placement advice file** for `tracemaker-place` (`--place-advice FILE`, only with `--mode routable` or `eco`), JSON version 1:
  `note`, `seeds` (at most 8, each a `name` and at most 64 `moves`), `eco` (at most 32 moves). A move is `ref`, `at` (footprint origin,
  mm, the board file's axes) and `rotate` (absolute degrees, default unchanged, the part's own orientation plus a multiple of 90).
  `src/place/place_advice.hpp`.
- Read strictly before any route: unknown key or reference, a reference that names two footprints, a part that is locked or otherwise
  fixed (rule 6, with the placer's reason), an orientation the part cannot take, a part moved twice in one seed, or more than the limits,
  is an error naming the entry. Side changes are not offered.
- A seed is the base placement with its moves applied. It is added after the placer's own seeds; one that adds an overlap or puts a part
  outside the board (the same test as the placer's seeds: new conflicts, or any with `--repair-input` / `--scratch`) is skipped with the
  reason. The loop keeps it only when it leaves fewer connections unrouted than every other seed, and the final verification route
  applies to it as to any winner.
- An ECO move is routed first in each ECO round (`EcoOptions::advised`, also the ECO step of each routability round through
  `LoopOptions::advised_eco`), on top of `--eco-candidates`, and committed only when it routes more. Moves that are not legal on the
  current placement, or were tried, are dropped.
- The JSON report gets an `advice` block (each seed: legal, why, unrouted, kept; ECO moves; whether the kept placement came from advice).

## Alternatives

- **The router's advice file with a placement key.** That file is read by `route`, which cannot move parts, and its strict reader would
  have to accept a key it ignores. A separate file for the program that acts on it keeps both strict.
- **An `--advisor CMD` loop for placement**, as the router has. Not built: no writer of placement advice exists yet, and doc 17 §8 found
  that the router's rule-based hints did not help. The file is the seam; a loop is worth building once a writer shows the file helps.
- **Advised moves instead of the ECO's own candidates** (within `--eco-candidates`). Advice would then take routes from the ranked moves;
  as extra candidates it cannot lose a ranked move (the same reason the router's advised variants are extra, doc 17 §4).

## Consequences

Unit tests (`[advice]`, `src/place/test_place.cpp`) and a CLI smoke test pass. An oracle (`bench/records/m16-stage4`: three boards with
their three largest movable parts turned by 180 degrees, advice that turns them back) shows the channel working (an advised ECO move
routed first and committed; a worse seed routed and not kept; a fixed part refused) and no gain: the placer's own candidates found the
same fixes. That advice adds value is not shown, as for the router's hints in doc 17 §8.1. Doc 17 §7, §8.3, §9; roadmap M16.
