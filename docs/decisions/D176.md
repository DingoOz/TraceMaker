# D176 — Kookabus boards as a private fixture set; unused pins are not critical nets

## Context

M21's A3 (doc 18 §4, §7) was the Kookabus boards as a fixture set, open since 2026-10-15 because the files were not on the machine. They
are now in `DingoOz/kookabus` (`~/Programming/kookabus`): six KiCad 10 projects with layouts (Kookabus-01, -02, -03, -04, -04H, -06; -05 and
-07 are still in planning). That repository is private and has no licence, while TraceMaker's is public. Doc 18 §8 predicted that B1 matters
little if these boards define no tuning profiles; A3 is where that is checked. Records: `bench/records/m21-a3`.

Routing the set with `--si-rules` showed one wrong audit result: on Kookabus-04H (a charge-only USB-C socket) the four unused D+/D- pins,
each on its own single-pad net (`unconnected-(J1-D+-PadA6)`), were reported as tier-2 critical USB nets.

## Decision

- **Fixture set, not files.** `scripts/fetch_fixtures.sh kookabus` clones the repository at a pinned commit (`PIN_KOOKABUS`, 293a922) into
  `bench/data/kookabus` (git-ignored); it needs read access to the private repository (`TM_KOOKABUS_REPO` may name another clone or a local
  path). `bench/sets/kookabus.txt` lists the six boards; `bench/prepare_demos.py --out build/kookabus --set kookabus` strips their routing
  as for the plane tier. No board file, rule file or routed output is committed: the records hold counts and measures only.
- **A critical net needs two pads.** `crules::critical_nets` skips a net with fewer than two pads: there is nothing to route and nothing to
  audit. Critical nets are computed only with `--critical-auto`, `--critical-nets` or `--si-rules`, so default routing is unchanged.

## Alternatives

- Commit the boards: they are the user's private designs with no licence; publishing them is the user's decision, not a fixture's.
- Skip nets by KiCad's `unconnected-(` name prefix: a user can rename a net, and a net with one pad is the actual condition.

## Consequences

- Measured (three arms, 3 M work, `--refill`, KiCad 10.0.6 judge): 1 of 6 boards clean (Kookabus-03), completion 85-100 %, no routing
  error added on any board in any arm; the designer's six layouts are all DRC-clean with nothing unconnected, so the set is a real gap.
- None of the boards defines a tuning profile, a length or skew rule, or an impedance class: B1 and B2 have nothing to act on here, as
  doc 18 §8 expected. The SI audit finds Kelvin current-sense pairs (INA/SNS) and one crystal; `--diff-pairs` couples Kookabus-06's sense
  pairs 95.9 % (designer 42.6 %).
- With the fix, Kookabus-04H has no critical nets; no plane-tier board had a critical net with fewer than two pads, so the plane tier is
  unchanged with `--si-rules`.
- The private repository means CI and outside contributors cannot run this set.
