# D193 — tui jobs screen and rerun advice

## Context

The user asked for a terminal screen that helps set up the route flags, monitors existing jobs, shows what is left to do
and what options each was given, and recommends what would change the outcome. The options half existed (`tracemaker
tui`, D89, D90). Every route run already writes its state to a live file once a second (D165), and finished runs carry
the router's diagnosis (`why_open.next`, doc 20 §2.5) in their `--json` summary.

## Decision

A jobs screen inside `tracemaker tui` (doc 02 §2.2), built like the options screen: `JobsModel` (keys in, lines out)
in `src/app/tui_jobs.cpp`, with no terminal code, and `advise(Job)`, a pure function from one job to advice. Each piece
of advice names the measurement it rests on, and those that change options carry them (`set`, `unset`). It can then be
applied to a rerun with one key, in the options screen's "this run" scope, so it is never saved by accident. `tui --jobs`
opens on it, `w` reaches it from the options screen, and `b` starts a run in its own process so the screen can follow
it. Nothing is changed on a job: the screen only reads files.

## Alternatives

- **A Python tool (curses or rich):** it would not share the option definitions, which the options screen reads from
  the parser, so advice applied to a rerun could not be checked by the same parser.
- **Advice from the engine only (`why_open.next`):** it does not know the measured campaign results (relax, ramp,
  layers), which are the rules that most often changed srj20 outcomes. Both are shown.
- **Stopping or restarting jobs from the screen:** left out. A wrong key could end an hour-long run, and the screen does
  not need it to give advice.

## Consequences

The advice thresholds are measured on srj20 (BGA boards). The 11.5-crossings rule is the router's own F9 threshold;
the other rules quote campaign counts and may not hold on other boards. Unit tests cover loading a job's arguments into
the options screen and the advice for a two-layer job left open at its limit. The options-screen integration test is
unchanged and passes. Routing and placement are not touched, so the quick tier was not run.
