# D177 — Run report: what the outside review of D3 found, fixed

## Context

The gate of doc 18 D3 (milestone M20) asks for a review of the run report ([D136](D136.md)) by someone who did not write it. One was
made on 2026-11-08 by a separate AI agent that had no part in the code and was given only the eight plane boards' reports, summaries and logs
and the how-to (`bench/records/m20-run-report/outside-review.md`). It is not a human review. Every number matched its JSON field and the log;
the errors were statements: the report called congestion "fixed copper encloses a pad" while the run's own exact proof (`why_open`, doc 20
§2.4) said no pin was walled in, and left that proof out; it said two USB pins of RoyalBlue's U5 could never escape although the router had
routed both; it left out starved thermal reliefs while saying 0 DRC errors; it explained connections the relax rescue's legalising round left
open as "the run ended before the router tried it again"; the summary of a rescued run said 0 expansions; the SI sentence claimed checks that
had not run. Ten findings were misleading and several unclear.

## Decision

- **The report carries the diagnosis.** `why_open` gets `neck_pins` (pin, net, the proof's sentence: the narrower track or smaller via that
  gets out). The report opens "What is open and why" with the diagnosis (pins walled in, out only with a smaller track or via, walled in
  only by fills, open through congestion), and the header prints each `why_open/next` line as "Next:". The `boxed_in` cause is described as
  the router's lattice check at the time it tried (pads, keep-outs and the copper routed by then), pointing to the diagnosis; the router's
  own "fixed copper encloses the pin" wording, which was never a proof, becomes "given up: boxed in on the routing lattice, even with routed
  copper negotiable" (the reason code is unchanged; summaries of older versions still map to `boxed_in`).
- **Pins that cannot escape are those the exact proof confirms.** The stuck report's package analysis (`route/escape.cpp`) searches a 40 µm
  lattice; its dead pins are now checked with `analysis::EscapeAnalyser` (`StuckInput::confirm_dead`, set by `route --report`), and those
  it does not prove enclosed go to the package's `not_proved` list. RoyalBlue's U5 12/13 (USB_DIFF class, 0.125 mm track, 0.203 mm clearance)
  had no way out on that lattice; the exact proof finds one, and the router routed both. The advisor's stuck report is unchanged (no hook).
- **Starved thermal reliefs are reported**: `refill/starved_thermal_pads` names them (pad, net, layer, place); the header warns, and a "Zone
  refill" section shows the refill, the refill repair (routed, kept, expansions) and the thermal repair.
- **The relax rescue is shown**: a "Relax rescue" section with each pass (routed under the board's rules, kept, seconds) and its relaxed
  stages (`rescue/passes/*/relaxed_stages`: clearance lowered by, routed; from `PortfolioResult::ramp_stages`). Variant rows get `best`
  (best of its pass) and, for rescue rows, `rescue_kept`; the report's variant table has a pass column.
- **Work of a run of rounds is summed over its rounds** (`PortfolioResult::work`, and the kept result's `work` and `expansions`, which are
  its variant's over every round). Before, each round's results replaced the last's, so a run of rounds reported its last round only, and a
  relaxed run its legalising round, which does no work (interf_u: `expansions` 0). A one-round portfolio reports what it did before.
- **The legalising round says what it left open**: it does not search, so a connection it leaves open gets a `why` of its own ("its route of
  the relaxed round broke the board's clearance ..." or "open in the relaxed rounds too ..."); its reason code stays `not_attempted`, whose
  description now names both cases.
- **DRC**: `drc/before/error_items` lists the input board's errors with their place, and the header warns about them; with the router's open
  nets, each unconnected item after the route says whether its net is one the router left open (`open_by_router`), and `after` counts both
  (`unconnected_open_by_router`, `unconnected_cut_by_refill`). `drc::Violation::net` carries the net of an unconnected item.
- **SI**: the audit section names only what the given options turned on and lists the rest as not checked; the critical-net table gains
  splits and the return detour, with a note on how they relate to the warnings (`critical_nets/detour_listed_over_mm`).
- **Clarity**: KiCad names are unescaped in the report (`report::kicad_unescape`: `{slash}` as `/`, `~{RESET}` with an overline); X/Y of a
  missing connection are of its From end; a board minimum of 0 reads "not set"; the header's section references are links; the copper
  layer count and the kept result's own expansions are in the Result table; the rules section says which of minimum and class governs.
- **Crystal roles** (`crules/detect.cpp`): XL2, OSC2 and CLKO name an oscillator output; when pins are named but neither name says which is
  the output, the last pin is xout, as for unnamed pins, instead of calling both xin.

The renderer still prints only fields of the summary, every value in the HTML carries its JSON pointer, and its own words hold no digit
(`tests/test_report.cpp`, extended for every new section). All new summary fields are additions; the renderer handles their absence, so
`tracemaker report` renders summaries of older versions as before (with the lattice caveat in the boxed-in text).

## Alternatives

- Dropping the lattice escape analysis from the report and keeping only `why_open`: the analysis also covers pins of routed connections
  and gives the package view; with the exact check it is right, and the advisor still has the lattice view it was tuned on.
- Filtering dead pins by "the router routed them": catches E2 but not a lattice-dead pin of an open connection that the exact proof frees
  (plane_smd's U2.B2, which gets out with a 0.25 mm via).
- Changing the boxed-in search itself so that its verdict is exact: a routing change, out of scope for a report fix (copper must not change).

## Consequences

- Routed copper is unchanged: the routed boards of the comparison runs are byte-identical to `main` 057ee82 (README §4 of
  `bench/records/m20-run-report`). Summaries of multi-round runs (relax, `--rounds`, breakout boards' four rounds) now report more work,
  the work they did; anything that compared those fields across versions (`bench/agent_eval.py` reads `work_all_variants`) sees the change.
- Findings not fixed, and why, are listed in the README §4. The gate's "someone who did not write it" is met by an AI reviewer only; whether
  a human must still read it is left open in `dev/progress.json`.
