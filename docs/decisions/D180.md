# D180 — Session daemon and the KiCad action that routes selected nets through it

## Context

M18's deliverables were the session and its transports (built 2026-10-15, D119) and "a long-running board session (`tracemakerd`) holding
the board and caches ... the plugin routes selected nets through it", with the gate "single-net route from the plugin within a stated
latency on `multichannel_mixer`, one undo step". The daemon and the plugin half were not built (doc 19 §9.5).

## Decision

- `tracemaker daemon` (`src/session/daemon.hpp`): sessions held between processes on a Unix-domain socket only its owner can reach
  (directory 0700, socket 0600; default `$XDG_RUNTIME_DIR/tracemaker/daemon.sock`, else `/tmp/tracemaker-UID/daemon.sock`), JSON lines,
  clients served one at a time. Requests `status`, `open`, `call` (= `Session::call`), `diff`, `mark`, `close`, `shutdown`. Exits after
  `--idle-exit` seconds without a client (1800); at most `--max-sessions` sessions (4, least recently used closed). A session reads its own
  copy of the board and project files. A second daemon on a live socket refuses to start; a stale socket file is replaced.
- `Session::copper_diff(from)`: the session copper the current state has and `from` does not, and under `removed` the reverse, in the
  `--emit-items` layout.
- **Reuse by the client's fingerprint.** `open` with `key` and `fingerprint` returns the session whose current state was `mark`ed with that
  fingerprint, without reading a board; anything else starts a new session from `board`, replacing an older one with the same key. The
  daemon compares strings only.
- **The KiCad action** "Route selected nets with TraceMaker" (`kicad_plugin/tracemaker_route_nets.py`): nets of the selection; fingerprint
  = SHA-256 over KiCad's deterministic serialisation of every track, via, footprint and zone (with fills), sorted, plus the `.kicad_pro` and
  `.kicad_dru` files on disk; daemon started on first use; `route` for those nets (`TRACEMAKER_NET_WORK`, default 2 M, `verify: refuse`);
  the diff added in one commit; the new state marked with the board's new fingerprint.

## Alternatives

- **Recognise the board by its file bytes.** Every action changes the board (the commit), so the next save never matches: no reuse in the
  one case that matters, routing one net after another.
- **Recognise it by parsing the board in the daemon and comparing copper.** Robust, but costs the board read that the daemon is there to
  save, and needs a canonical comparison of KiCad's and the engine's copper.
- **Keep a router between calls** (the set-up, about 0.8 s on `multichannel_mixer`, is most of a short net's latency). A larger change to
  the router's life cycle; not built until the latency matters.
- **TCP.** Reachable by other users and machines; a Unix socket in a 0700 directory needs no token.

## Consequences

In a running KiCad 10.0.6 (`scripts/kicad_gui_roundtrip.py --nets`, `bench/records/m18-daemon`) on `multichannel_mixer`: a 2-pad net is
routed in 1.75 s (new session) or 1.59 s (warm), an 11-connection net in 4.04 s / 3.78 s; one undo removes only the last net's copper;
no new KiCad DRC error. The gate of M18 is met as stated; its stop rule for agents (doc 19 §7) is unchanged and nothing for agents is built
on the daemon. Unsaved changes to the board setup that are not in the project files are not in the fingerprint (documented: save after
changing rules). Unix only (the plugin's other action has no such limit). Doc 19 §5, §9.5, §10; roadmap M18; `kicad_plugin/README.md`.
