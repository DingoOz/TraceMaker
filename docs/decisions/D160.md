# D160 — Relax rescue by default: a plain run that leaves connections open is routed again with relax

## Context

D159 (doc 05 §67) made `--relax` keep its routes through the hand-overs on boards with rotated, oval and rounded pads. On the 33 failing
PCBench tier B-D boards, relax still lost to the plain run overall (−241 connections). It did complete boards the plain run did not
(serial_gw, teensy-fx, ardfpga), and the better of the two per board gave +42 connections and five clean boards against two. Nothing
ran relax unless the user asked for it, so a hard board got only the plain portfolio. Asked for: "we want that escalation as the
default behaviour".

A run without `--work` stops on its time limit (120 s by default). On four hard boards the plain portfolio used all of it and was still
working (two passes on poncho), so there is no time left over to give a rescue.

## Decision

- **The rescue** (`app/route_job.cpp`, after the plain run, before the advisor). When the plain run leaves connections open and
  `--relax` was not given, the board is routed again from nothing with `--relax`. Its result is kept only if
  `route_result_better` prefers it (more routed, then fewer vias and shorter copper). A tie keeps the plain result, so no board ends
  worse than the plain run.
- **Its own budget.** `--time` again, as the advisor's re-run gets. With `--work`, rounds of at most 20 M work that add up to
  `--work` (100 M gives 5 rounds of 20 M, the settings measured in D159). A board left open can take up to twice as long. A complete
  board never gets a rescue and is unchanged.
- **On by default**, `--no-rescue` turns it off. Only `tracemaker route` has it; placement's internal routing and `tracemaker session`
  do not.
- The run summary gets `rescue` (routed before and after, kept or not, seconds). `bench/run.py` copies it into `boards.jsonl`. The viewer
  gets `rescue` stage events. The knowledge base records a run the rescue won as one no plain variant won.

## Alternatives

- **Split `--time`** between the plain run and the rescue. Wall time would not grow, but the plain run would get less time on exactly
  the boards that need it, so some would end worse than before.
- **The rescue only with `--work`.** Time-limited runs, the default, would not get it.
- **`--relax-late`** (plain rounds first, relax when they stall, one budget). A stopped run on 16 of the boards was 5 connections behind
  the plain run: its plain phase gets less work.
- **Warm-starting relax from the plain result.** Not measured. The rescue is the run D159 measured, so the gain is known.

## Consequences

- On the 33 failing PCBench tier B-D boards (100 M work, KiCad-judged):

| Arm | Routed (of 16,935) | vs plain | Better / worse | KiCad-clean | CPU s |
|---|--:|--:|--:|--:|--:|
| plain (main) | 16,166 | | | 2 | 64,062 |
| `--relax` alone (D159) | 15,925 | −241 | 8 / 15 | 5 | 60,232 |
| default with the rescue | 16,208 | +42 | 8 / 0 | 5 | 110,958 |

  Every board is the better of the plain run and relax. The rescue ran on the 30 boards left open and was kept on 12; serial_gw,
  ardfpga and teensy-fx complete clean. No board added a DRC error. CPU is up 73 % on this set, where every board is left open.

- Quick tier (`--work 1000000 --variants 1`): the rescue ran on the 19 incomplete boards and was kept on 8. 22 of 30 boards
  byte-identical, +11 connections, 12 clean boards against 11 (C-BISCUIT completes). Gates pass. Each rescue took 1-3 s there.
- Benchmarks that leave boards open take longer: those boards are routed twice.
- Relax's copper has more off-angle segments (the legaliser moves vertices off the lattice). Style is informational.
