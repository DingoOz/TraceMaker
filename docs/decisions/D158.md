# D158 — Small cost-to-go fields on the CPU

## Context

After M22, every repair came within a few connections of the base given about 10 % more work, so the next step was to get more
routing out of the same time ([doc 05 §66](../05-routing.md), records in
[bench/records/m23-throughput](../../bench/records/m23-throughput/README.md)).

A gprof profile of Aleste (variant 5, 20 M work, CPU fields) and timings of both boards gave this picture:

- **Aleste.** Fields took 17 % of the CPU time. Against the GPU, the CPU fields were faster here: 4.4 s against 5.7 s for 482 fields
  on a 1,721 × 1,017 × 2 lattice.
- **mini_mass.** On its 9,385 × 1,847 × 4 lattice the GPU was three times faster: 25 s against 71 s.
- **Cost model.** Per field cell the CPU costs about 72 ns and the GPU about 26 ns, plus about 8.5 ms per field on the GPU. That
  fixed cost covers the device memory query, five allocations, unpinned copies and a synchronisation after every round of 8 to
  33 kernel launches.
- **With eight variants.** The variants share one GPU, so a variant waits longer for each field.

## Decision

A field with fewer lattice cells than `gpu_field_min_cells` (width × height × layers; default 500,000; hidden option
`--gpu-field-min-cells`) is computed on the CPU, and larger ones on the GPU as before.

- **Same output.** The two give identical fields; that is what the existing tests check. So the routes are identical too.
- **Counters.** A field sent to the CPU this way is not counted as a GPU fallback.
- **Skipped lookup.** The learned-block lookup in `cell_cost` is skipped when the set is empty: 20 M tree lookups on Aleste for a
  set that was empty. This is also output-identical.

## Alternatives

- **All fields on the CPU** (`--no-gpu`). It wins on Aleste but loses 46 s on mini_mass.
- **Fewer GPU round trips.** Persistent device buffers, pinned host memory, or checking for convergence every few rounds would cut
  the fixed cost. None of that was built: below the threshold the CPU is faster anyway, and above it the kernels dominate.
- **A routed-copper state cache across searches.** Legality checks against routed copper are about a quarter of the CPU time. Of
  11.8 M such checks on Aleste:
  - 31 % repeat the same net, cell and width;
  - 81 % repeat the same cell and width for any net.

  Both are upper bounds, since commits in between invalidate some. A cache that serves every net would have to keep the routed
  items near each cell and drop them around every commit. Not built yet.

## Consequences

Wall time at 20 M work, byte-identical output (`fields/`):

| | 1 variant, threshold 0 | 1 variant, 500 k | 8 variants, 0 | 8 variants, 500 k |
|---|--:|--:|--:|--:|
| Aleste | 27.35 s | 25.51 s | 33.45 s | 29.55 s (−11.7 %) |
| mini_mass | 65.61 s | 63.68 s | 85.89 s | 78.51 s (−8.6 %) |

- The quick tier is byte-identical on all 30 boards (`quick-split/`).
- Test: `fields split between the CPU and the GPU by size route exactly as all on one of them` (`tests/test_gpu.cpp`).
- Docs changed: doc 05 §66.
