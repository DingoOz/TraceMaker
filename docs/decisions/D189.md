# D189 — CPU fields skip the rows that cannot change

## Context

M23 E5 (doc 18 §20): more routed at equal wall time. On the 33 failing boards 8× the work leaves 41 % fewer connections open
(`bench/records/m23-e5`), so cheaper work is worth having. In the profile the CPU field is the largest single cost (22 % of a one-variant,
CPU-field run). Fields under 500 k cells run on the CPU even with a GPU (D158), and every field does without one.

## Decision

- `gpu::field_cpu` skips a row's step when it cannot change anything. Along a row: the row is unchanged since the same (layer, direction)
  sweep processed it. Across rows: the predecessor row is unchanged since then. Via step: no layer of the row changed. Ticks per (layer, row)
  and per (layer, direction, row) decide this. The field, each sweep's change flag and the round count equal `field_cpu_reference`'s.
- The GPU kernel and the GPU threshold (`gpu_field_min_cells`, 500 k) are unchanged.
- Doc 05 §83.

## Alternatives

- **A 4-ary heap for the open list** (same pop order, so the same routes): 0.4-0.5 % of wall time. gprof had put the heap at 9 %, mostly its
  own per-call cost. Not kept.
- **Dijkstra (or a bucket queue) for the CPU field**: the same unique distances, but a heap per cell, where the sweeps are vectorised.
  Skipping rows gave the larger share of the gain with no change of algorithm.
- **Raising the GPU threshold now that CPU fields are cheaper**: every field on the CPU made the eight-variant mini_mass run 36 % slower
  (80 s against 59 s), so the threshold stays.

## Consequences

CPU field cells cost 25-41 ns instead of 53-79. Runs are 3-27 % faster with one variant and CPU fields, and 4-9 % faster with eight
variants and the GPU. Every output tested is byte-identical: three profiled boards, two portfolios, and the 30 quick-tier boards. At equal wall time
(`--time-total 120`, 33 boards) the difference is within the noise (+13 with the GPU, −18 without). The gate of doc 18 §20.2 is not met,
and E5 stays open. The remaining costs (search loop, routed-copper and fixed-copper checks) have no single large term.
