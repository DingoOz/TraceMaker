# D181 — --txn 1 stays off by default after the tier A-D run

## Context

M17's C1 run (doc 10 §11.3, D122) found `--txn 1` (negotiation as transactions, D99) routing +118 connections on the 33 failing tier
B-D boards at equal work, with no board completed, and left open whether it should become a default portfolio variant: that needs
tiers A-D at equal wall time. Run on 2026-11-13: both arms at once, `--time 120 --threads 8 --jobs 3`, tiers A-D at the release
limits (doc 10 §11.4, `bench/records/m17/README.md` §5).

## Decision

`--txn 1` stays as D100 set it: on for breakout boards (with `--txn-temp 1.5`), off elsewhere. No portfolio variant gets it by default.

## Alternatives

- **On for every variant** (the arm measured): 95 → 94 clean on the 108 boards both arms finished (`m2-electronics_m2fc` lost, none
  gained), +34 routed connections of 22,937, all on boards that stay open, 20 harness timeouts against 17.
- **On for one or two of the eight variants**: not run. The all-variant arm gains no clean board, so a partial portfolio would at best
  match the base on clean pass while spending variants on it; not worth a third run of the tiers.

## Consequences

- Nothing changes in the code. The option stays available for boards that stay open (up to +15 connections on such a board).
- 37 board results (17 base, 20 `--txn 1`) were lost to the harness's stop of 3 × `--time` + 60 s, which is shorter than the designed
  budget of a board left open (plain portfolio plus two rescue passes). Only an open board reaches the rescue, so the two base-clean boards
  that timed out with `--txn 1` alone (serial_gw_ATMEGA328P, mechkeys_58r-mxalps) are very probably two more losses. The harness stop is
  raised in D182.
