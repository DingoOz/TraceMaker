# D187 — Octilinear doglegs after the route

## Context

M23 E3 (doc 18 §20). After any-angle smoothing, about one new segment in seven on tiers A-B is off the eight directions (3,659 of 24,433),
which designers read as unfinished work (user point 1).

## Decision

- `route --octilinear`: an after-route pass (`src/passes/octilinear.{hpp,cpp}`) replaces each new, unlocked off-angle track with a dogleg on
  the eight directions, diagonal or straight leg first. A dogleg is used only if both legs pass the router's exact check against everything,
  including doglegs already made. Ends never move.
- No leg shorter than `--octilinear-min-leg` widths (**default 0.5**) and no acute corner with copper of the same net, layer and point.
  Bounded by `--pass-work` checks, and judged by `no_worse` like the other after-route passes.
- **Off by default in the engine, on by default in the KiCad plugin** (`"octilinear": true`).
- Doc 05 §80.

## Alternatives

- **Minimum leg 1 width**: −23 % off-angle against −39 %; it misses the gate of a third fewer.
- **Rerouting off-angle connections on the lattice**: it costs search work and can lose routes. The dogleg is local, and its check is the
  commit check.
- **On by default in the engine**: it changes the copper of every board, and every record against the old output. The plugin, where the board
  goes back to a designer, is where it pays.

## Consequences

On tiers A-B at 3 M work: off-angle segments 3,659 → 2,245 (−39 %), with routed, clean and DRC errors unchanged and the same wall time
(`bench/records/m23-e3`). The cost is 712 more segments shorter than their own width (legs of half a width to one width). What is left is
mostly between fine-pitch pins, where neither dogleg fits.
