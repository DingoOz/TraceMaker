# D165 — Live page of every process and bench run

## Context

The user asked (2026-10-31) for "a single page that is real time updated that shows lots of details of whatever (including
parallel boards) tracemaker is doing ... default on always". What existed did not do that. The viewer (doc 09) shows one run and
needs `--view`. `devsite/live.py` is started by hand for one bench run, refreshes every 30 s and only knows queued, running or
done. The progress site on :8765 reads `bench/results` of the checkout it runs from, so runs in other worktrees were invisible.
Parallel boards and the variants of a portfolio could not be seen at all.

## Decision

Every process publishes its own state to a shared directory. One page on the progress site reads the directory.

- **Engine** (`src/core/live.{hpp,cpp}`): `main()` starts a detached writer thread. It writes `<dir>/<pid>.json` once a second
  (to a temporary file, then renamed). `<dir>` is `$TM_LIVE_DIR`, else `$XDG_CACHE_HOME/tracemaker/live`, else
  `~/.cache/tracemaker/live`. It is on by default and `TM_LIVE=0` turns it off. A process that ends within its first second
  writes nothing. The file holds:
  - the command line, cwd, binary, version, pid, parent pid and `/proc` start time;
  - fields set by the route job: board, output, budget, viewer port, stage, round, last round, result;
  - one slot per router (a portfolio variant, by name) with routed, total, work in progress and its budget, work over all
    runs, phase and runs;
  - a history of the best variant's routed count, work and CPU time (720 samples, halved when full);
  - the last 200 log lines (the job's log and the portfolio's round messages);
  - the final state (`done` with the exit code, or `ended` after `std::exit`).
- **Routers** update their slot with relaxed atomic stores in `emit_stats`, which runs after every routed connection. This
  happens before the check for a viewer sink, so it works without `--view`. Nothing in the engine reads any of it back, so
  results cannot change (rule 2).
- **bench/run.py** (`bench/live_run.py`) writes `<dir>/run-<pid>.json`: the run, set, worktree, commit, budget, boards, each
  running board's step (placing, routing, judging) and every finished board's row. It gives each tracemaker process it starts
  `TM_LIVE_RUN` and `TM_LIVE_BOARD`.
- **Progress site**: `/live` (static `live.html`) polls `/api/live` (`devsite/livefeed.py`) once a second.
  - A board's process is shown under its bench run (same run name, the run's pid as parent). Other processes are listed
    on their own.
  - `/proc` adds CPU use, memory and threads for live processes. A process whose file says running but whose pid (with the
    same start time) is gone shows as killed.
  - Ended runs stay visible for 30 min by default (10 min to 24 h on the page).
  - Each process's worktree and branch come from its binary's path, so every checkout shows up.

## Alternatives

- **Have the page attach to every viewer WebSocket.** That needs `--view` on every run. A sink also turns on the heavy events
  (frontiers, heatmaps), and the page would get no information about bench runs.
- **Parse the stdout logs of bench runs.** bench/run.py keeps child output in temporary files until a board ends, and
  standalone runs log wherever their caller sends them.
- **One central server that processes push to.** That makes every run depend on a server being up. The file per process
  needs nothing running, and the page can be restarted at any time.

## Consequences

- Every `tracemaker` command that runs over a second leaves a small file in `~/.cache/tracemaker/live` (about 4-30 kB,
  rewritten once a second). Files older than a week are removed when a process starts.
- Only binaries built with this change, and bench runs from a checkout that has it, appear on the page. Older run
  directories' snapshot binaries do not.
- The page is served by whichever checkout the progress-site service runs from. It needs this change on that checkout's
  branch.
- Docs: doc 09 §9 and the how-to `how-to/live-page.md`.
